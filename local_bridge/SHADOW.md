# 日内影子版本 intraday-shadow-v1

现有 technical-structure-v3 分析、predictions 表、正式两小时统计口径保持不变。影子数据单独保存在本机 aurum.db 的 shadow_forecasts 表，网页和报告增加独立展示。

- 北京时间工作日06:00：生成草稿，08:00失效，不结算、不计样本。
- 工作日08:00：重新生成日内定调并冻结，次日06:00失效。同日重复运行不覆盖。仅允许时点后10分钟内生成，停机错过不会事后补造。
- 复用现有每两小时调度（包含06:00、08:00），不增加重复任务。内置服务使用固定北京时间；Windows任务计划使用系统时间，本机已核对为China Standard Time。
- 每两小时生成独立影子短线；手动和21:00补充只展示约束，不记入影子两小时样本。同一两小时槽位最多一个影子样本。
- 日内方向由已完成D1的MA20、MA60及5日变化评分产生。概率为未校准的技术启发式，不代表已验证的成功率。日内支撑阻力来自前20个已完成D1，宽度为日ATR的5%。
- ATR口径：经纪商D1，前14个已完成日线真实波幅的简单平均。当日已运行空间为当前经纪商D1最高减最低；剩余为max(0,ATR-已运行空间)。不是北京时间零点重置，也不是某一方向保证可走的距离。
- 同向沿用v3评估；不同方向（包括震荡与方向性判断不同）视为冲突，将三项概率按70%原值+30%均匀分布收缩。冲突须最近已收盘M15收盘突破此前20根已完成M15的高/低点，才能保留有条件评估。
- 日ATR使用达到80%时禁止追单，影子版本进一步保守地暂停新入场。定调缺失/过期、新闻不完整或行情过期同样暂停；这些约束不修改v3预测。
- 新闻风险保存抓取错误及事件清单。现有日历源时区信息不统一，明确提示事件时间需核实，不把新闻抓取成功当作没有风险。
- 影子结算逐条读取对应起止时间的M5历史；使用到期前最后一根完整M5收盘，不使用未来价格。起始部分K线排除，起止历史缺失保持待结算。方向震荡阈值为起价±0.15%；分别统计日内/两小时方向命中率和Brier。
- 30个交易日以已结算冻结日内样本的不同日期计数，草稿、停机、缺失行情不凑数。达到30天只标记可复核，永不自动晋升或替换v3；所有历史保留。
- 调度失败在原有3分钟窗口内重试；长期停机仍会漏时点，应保持电脑、MT5和本地服务在线。影子异常会显示在dashboard的shadow_error和报告中，原有主流程继续。

验证：在项目目录运行 `python -m unittest discover -s local_bridge -v`。测试使用临时账本，不连接MT5、不发送通知、不修改生产统计。上线当天不能声称已完成30个交易日验证。

## 构建和自动验证

项目通过package.json的devEngines.runtime和锁文件固定Node 22.23.2，GitHub使用同一.node-version。安装依赖后，pnpm run build会自动使用此运行时，避免本机Node 24构建完成后的Windows退出断言错误。

GitHub Pages发布前运行Python 3.12单元及工作流测试；测试使用临时账本和模拟行情，不连接交易终端或通知服务。真实手动核验使用--manual --no-push --no-publish，排除正式统计；休市过期行情不会生成影子有效样本。
